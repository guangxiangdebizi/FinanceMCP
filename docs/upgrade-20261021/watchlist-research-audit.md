## 已确认实现问题与兼容处理

原 `evidence.ts` 的全市场均值未过滤 SQL NULL；JavaScript求和把 NULL当0，而池成员会过滤有限数。内存合成两只股票（收益10%、NULL）可产生错误5%的市场均值并凭空增加5个百分点超额。本次通过独立修正审计显露差异，不重写原报告或覆盖历史证据。后续已在 `evaluateWatchlist` 中先过滤非有限收益再计算全市场均值与最小样本数（`test/upgrade-phase34-review.test.mjs` 以 10%/NULL/0% 三只合成股票验证市场均值为 5% 而非 3.33%）；不存在 NULL 收益时结果与此前逐位相同，已存报告不重写。

旧 `pending_dates` 同时包含未成熟、基准不足和池缺数，`members` 只表示已定价成员，不能表示所有原成员。新审计逐日保存 selected/priced/unresolved 与端点基准覆盖，明确区分跳过原因。旧日报文字“近60个交易日内”实际取65交易日以得到最多60个成熟日期；缺少历史日报或基准时并不会自动向前补够60日期。

旧信号证据使用10日主分类，日报股票池用5日观察，二者不是同一个检验。信号证据按个股有价bar计horizon，遇停牌可能跨股时间不同；新研究使用交易所日历。当前 ST、行业、上市元数据与历史修订源不能完全还原到原始时点，该偏差仍披露，不伪称已解决。
