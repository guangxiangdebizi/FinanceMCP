# A 股 Phase B：版本化分析与历史研究

本分支新增独立分析与评价入口；所有新结果标为 `RESEARCH_ONLY`。正式 `daily` 仍通过原来的 `scanMarket()`、`updateWatchlist()` 和 `generateReport()` 使用 `score-1.0.0`、`sig-1.0.0`、`wl-1.0.0`、`evi-1.0.0`。本轮不更新生产容器、systemd timer 或 ChatGPT 定时任务。

## 分析契约

`src/ashare/engine.ts` 的 `analyzeMarket(db, request)` 接受日期、评分版本、股票范围和明确支持的研究参数。计算完整市场的可评分集合后才筛选返回的股票，因此同一股票的分位数和排名不会随查询范围改变。函数不发布报告、不更新股票池、不写入数据库。

`ashare_factor_snapshot` 为同一引擎的只读 MCP 入口。必须提供 1–20 个 `ts_codes`，可选 `date`、`score_version`、`include_components`。例如：

```json
{
  "date": "20261016",
  "ts_codes": ["600519.SH", "600938.SH"],
  "score_version": "score-2.0.0",
  "include_components": true
}
```

结果包括原始因子、标准化因子、实际代入公式的因子、缺失值默认规则、加权贡献、总评分、排名、准入与剔除原因、财报可用日期、信号触发/失效条件、数据质量及历史局限。当日没有行情的指定股票返回缺失状态，不拿前一日行情代替。

原始测量缺失时为 `null`，不能与公式中的中性默认分混淆。源数据的 `NULL`、非正或内部不一致的 OHLC 也会使依赖价格序列的技术观测（`ret20/ret60`、MA 趋势、`rsi14`、`atr_pct`）返回 `null`，并抑制该股票的研究信号；扫描窗口内的 20 日成交额缺失同样使流动性观测为 `null`。原因写入 `quality.risk_flags` 与 `imputations`。这些披露不改变 V1 的历史评分和排名，旧公式代入值与贡献仍原样保留，便于审计。`normalized` 表示有观测依据的归一化值；`scoring_factors` 与 `imputations` 明确展示为了兼容 V1 而代入的默认值。现有 V1 的历史缺失处理也须在新契约中披露。

| 因子 | 原始单位 |
|---|---|
| ret20、ret60 | 小数收益比，0.20 表示 20% |
| MA20、MA60、close | 元；复权趋势指标转换回 as-of 原始价位 |
| RSI14 | 0–100 指数 |
| ATR14 / close | 小数比值，0.04 表示 4% |
| amount20_yi、circ_mv_yi | 亿元 |
| pe_ttm、pb | 倍数 |
| roe、netprofit_yoy、ocf_to_profit、debt_to_assets | 百分数，115.11 表示 115.11% |
| industry | 当前 Tushare stock_basic 分类，不是历史时点行业 |

技术收益窗口是最近有行情的 K 线数量，遇停牌或缺口可能跨越更多交易日；历史评价的持有期则严格按交易所日历计数。

## 评分定义

`score-1.0.0` 保留原公式和股票池规则。研究候选 `score-2.0.0` 仅将现金流比例满分阈值从原始百分数 `0.8` 修正为 `80`：

| 原始 ocf_to_profit | V1 cash | V2 cash |
|---|---:|---:|
| 115.11% | 1 | 1 |
| 20% | 1 | 0.5 |
| −10% | 0 | 0 |
| 缺失 | 0.5 | 0.5 |

两版权重均为技术 35、流动性 15、基本面 30、估值 10、行业 10。基本面组件是 ROE 分位数、利润增速分位数、cash、leverage 四者均值。因此 0.8% ≤ 原值 < 80% 且有可用财报的可评分股票，V2 在未舍入贡献上减少 `30 / 4 × 0.5 = 3.75` 分；其他分项保持相同。各股票分别保存两版因子贡献，不由总分差推测原因。

银行、证券、保险、多元金融继续使用相同的 cash 阈值，以免将未经验证的行业调整混入本次单位修正；这不表示现金流口径跨行业等价。金融行业的杠杆仍为中性 0.5。ROE 为负仍按两版原有准入规则剔除；EPS 非正单独标注利润分母含义不确定，不能凭 EPS 重构供应商 `ocf_to_profit` 分母。缺失、零或负利润分母未能从现有缓存验证时，不宣称比例有可靠经济含义，也不擅自改变其他评分规则。

## 评价契约

`src/ashare/evaluation.ts` 的 `evaluateEvents()` 只消费已经在 t 日收盘确定的事件，不用后续收益重新选股。其约定为：

1. t+1 交易所开盘价是唯一买入时点；缺失行情不移动到下一根 K 线。停牌、零成交量、开盘达到涨停价保守拒绝买入。涨跌停价或成交量缺失记为未知。A 股 T+1 不允许当日卖出，因此按当前 `t+h` 退出定义，持有期必须 `h ≥ 2`；`h=1` 直接报错，默认 `h=10`。
2. 计划在 t+h 收盘退出。停牌或已知收盘跌停导致卖出受阻，可在显式 `maxExitDelay` 内延后；行情或成交约束无法确认时保留无法退出事件。
3. 退市、没有后续行情、缺少复权因子和未到持有期的事件仍在总样本及状态分母中；不把它们当成零收益，也不静默删除。
4. 买卖费用与两边不利滑点均为显式 bps 参数。默认买入 3、卖出 8、每边滑点 5 bps，是研究情景而不是逐历史日期的税费还原。
5. 所有日期价格查询受 `asOf` 约束，研究规则形成段的收益也在固定切分点截断。

涨跌停规则是日线级保守近似。没有真实盘口和订单队列，不能声称已模拟封板排队、开板后的流动性或准确成交。停牌记录包括可能的部分日停牌；研究中统一按当日无法成交处理。

三种参照均用相同实际买入、退出区间：信号日上市股票全市场等权、沪深 300 价格指数、当前行业匹配等权。参照是无费用的端点收益观察，并非可交易组合；指数也不是可投资 ETF 或全收益指数。全市场/行业参照包含消失股票的成员分母，但无法定价时只报告已定价子集均值，并明确缺失数。完整覆盖与部分覆盖的超额统计分开列出，不能把后者称作无偏全市场收益。

输出分别包含事件数、入场数、完成数、未知/受阻/待到期/无法定价/无法退出数，收益和超额的均值、中位数、胜率、分位数、样本波动，按信号日均值的观察序列，以及不重叠日期组敏感性。敏感性以全部已入场持仓的区间为准：未确认退出的持仓按 `asOf` 截断计算，不能因为同组另一只股票已退出就忽略它；只有完全没有入场的日期才不产生区间，但仍计数列出。收益均值只基于已完成观察，未完成事件在分母中单列。合成观察序列回撤不是实际资金组合回撤。持有期重叠、重复股票和跨股相关性仍然存在；不计算容易误导的独立样本 t 值、年化 Sharpe 或统计显著结论。

相关性以有效配对样本计算并保留 n，包含因子/信号相互关系及其与收益/超额的关系。常量或有效样本不足返回 null。

## 可复现实验

`deploy/ashare/harvest-research.mjs` 从冻结的 V1 build 产生完整市场扫描；`deploy/ashare/run-research.mjs` 对同一输入同时评分 V1/V2，分别维护独立池状态，并用同一评价函数执行两个版本。

默认方案从 2024 年开始，先积累至少 130 个交易日，再每隔 5 个交易日采样；额外包括 2026-03-31 切分日和数据截止日。股票池仅在采样日按未修改的 `wl-1.0.0` 更新，因此这是具有独立初始池的采样调仓情景，不能冒充正式每日股票池的历史。默认持有 10 个交易日，主动保留重叠并报告敏感性。可以显式选择其他采样/持有参数，但不同参数必须保留为独立实验，不能调优后仍声称原验证未受接触。

### 三个时间区间（不得混用）

| 区间 | 起止 | 含义 | 状态 |
|---|---|---|---|
| 历史形成区间 | 2024-07 ~ 2026-03-31 | 规则在此区间形成，收益在切分点截断 | 已计算 |
| 回溯模拟验证区间 | 2026-04-01 ~ 2026-10-16 | 同一冻结快照上的历史模拟；数据在规则形成前已存在并被查看过 | 已计算，**不是样本外** |
| 真正前瞻观察区间 | 2026-10-19 起 | 规则冻结后逐日新增、不可回填的观察 | **PENDING** |

`2026-03-31` 只是历史回溯切分点。V2 于 2026-10-17 才形成，因此 **2026-04-01 至 2026-10-16 绝不能称为未接触的样本外结果**；它是已被部分观察过的历史模拟，只能用于一致性核对与描述性敏感性，不能作为策略有效性的独立证据。

### 统计口径

- 收益均值/中位/胜率只基于**已完成事件**，是条件观察值；未完成（已入场未退出）与未入场事件保留在完整分母中。
- 报告收益时必须同时给出**完成率**与**无法退出比例**；模拟区间尾部事件因持有期未结束而保持 `pending`，不能按零收益或假设收益处理。
- V1/V2 的完成事件集合不同，两版均值差**不是严格配对的策略收益差**。`verify-research-summary.mjs` 另行计算共同可比较事件（同日期同股票）的配对差：该差在构造上恒为 0（同一事件、同一评价函数、同一数据截止日），说明版本差异只来自池成员，而非收益计算。
- 基准超额条件于**已定价子集**：全市场与行业基准按事件均为部分覆盖，完整覆盖与部分覆盖分别统计，缺失成员数单列。
- 持有期重叠、重复股票与跨股相关仍存在；不计算独立样本 t 值、年化 Sharpe 或统计显著性。
- 未因 V2 在历史模拟中表现较差而修改任何权重、阈值、股票池或信号规则。

```sh
npm ci
npm run build

# 先用 SQLite backup 产生冻结副本；不要把研究输出指向正式目录。
sqlite3 /path/to/live/ashare.sqlite '.backup /path/to/research/ashare-20261016.sqlite'

# baseline-build 是 e8cbe4a 编译出的 build 目录。
node deploy/ashare/harvest-research.mjs \
  --source /path/to/research/ashare-20261016.sqlite \
  --build /path/to/baseline-build \
  --output /path/to/research/phaseb --workers 2

npm run ashare:research -- \
  --source /path/to/research/ashare-20261016.sqlite \
  --inputs /path/to/research/phaseb \
  --output /path/to/research/phaseb
```

研究库保存 `experiment`（协议与完整结果）、`factor`（原始因子）、`score_version`（两版标准化因子及贡献）、`pool`（版本独立池状态）、`event`（逐事件完整结果）。所有表都带 `run_id`，评分和事件同时带版本。`run_id` 由市场快照、冻结基线构建、每个扫描输入、日期、参数、版本、实现源码与运行时构建的 SHA256 共同生成。重新执行同一实验会在研究库中原子替换相同 ID，输出结果应一致。

仓库只保留精简证据 `docs/ashare-samples/phaseb-research-summary.json`（协议、逐日指标、分母、基准覆盖、质量状态、共同事件敏感性），完整 `summary.json`（2.3 MB）与研究库保留在研究输出目录；`deploy/ashare/compact-research-summary.mjs` 可从完整结果重发精简文件，`deploy/ashare/verify-research-summary.mjs` 逐项核实并输出 `docs/ashare-samples/phaseb-research-audit.json`。哈希与复现命令见 [Phase B 验收](ashare-phaseb-acceptance.md) §5.9。

最终结果、真实缓存验证、V1 一致性证据与验收条件记录在 [Phase B 验收](ashare-phaseb-acceptance.md)。
