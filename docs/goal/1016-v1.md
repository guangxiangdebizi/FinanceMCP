# FinanceMCP AShare：Oracle VPS 开发任务

你是负责 FinanceMCP A 股日频投研扩展的资深工程师。

## 目标

基于 https://github.com/guangxiangdebizi/FinanceMCP 的最新稳定源码，构建一个运行在 Oracle ARM VPS 上的轻量级 A 股日频数据和分析 MCP 服务，供 ChatGPT 网页版的现有 A 股日报定时任务直接调用。

已确认：ChatGPT 网页版定时任务已经能够成功调用本 VPS 部署的 XFullReader MCP 服务。优先复用现有 HTTPS、网络路由和经过验证的 MCP 接入方式，不再开展“ChatGPT 是否支持自建 MCP 定时调用”的研究。

现有 Tushare Pro 8000 积分权限，凭证由 VPS 环境变量(TUSHARE_TOKEN)提供。

## 架构硬约束

1. 只基于 FinanceMCP 开发，不引入 TactiCore。
2. 只使用 TypeScript / Node.js，不新增 Python 量化服务。
3. 只维护一个长期运行的 FinanceMCP 服务。
4. 数据缓存优先 SQLite，日报快照保存为 JSON。
5. 定时更新使用 cron 或 systemd timer，不开发自定义任务调度框架。
6. 不增加 Redis、Kafka、PostgreSQL、独立 Gateway、Agent 编排平台或新的 LLM 服务。
7. 优先复用 FinanceMCP 的 Tushare Client、MCP Dispatcher、现有金融数据工具和 Docker 部署能力。
8. 不修改与需求无关的现有工具，不引入通用量化平台架构。
9. 不实现实盘下单、自制撮合系统或复杂策略回测框架。
10. 必须使用真实数据完成验收，不得用 mock 通过就宣称系统已生产可用。

## 实施任务

### M1：打通日报最小闭环

读取 FinanceMCP 最新源码，锁定 Git commit，执行现有构建和测试。

验证 Oracle ARM64 环境、Node.js、SQLite 驱动、Tushare API 和现有 XFullReader 网络入口。

在 FinanceMCP 内增加 `src/ashare/`，实现：

- 交易日历查询。
- 股票基础信息和日线行情批量更新。
- daily_basic、adj_factor、index_daily 增量获取。
- 基础数据质量检查及 SQLite 持久化。
- 主要指数表现、成交额、涨跌家数及简单市场广度分析。
- 当日 JSON 研究快照。
- `ashare_data_status`、`ashare_daily_report` 两个 MCP Tool。

必须实现按交易日批量下载，不允许逐股下载整个市场；处理 Tushare 返回条数、分页、速率限制、异常重试和数据缺失。

在 ChatGPT 网页版手动调用以及已有定时任务中，验证真实 MCP 数据结果。

### M2：技术分析和股票池

在同一 `src/ashare/` 模块中实现：

- MA、RSI、MACD、CCI、BOLL、ATR 和成交量特征。
- 必要的技术指标口径校验和单元测试。
- 趋势、突破、背离等规则明确的技术信号。
- 市场环境及行业强弱分析。
- 基于流动性、技术面、基本面和行业分散的动态股票池。
- 每日评分、股票池增减和历史记录。
- `ashare_watchlist`、`ashare_stock_analysis`、`ashare_sector_rank`。

股票池目标 30～50 只，避免行业和主题过度集中。允许股票每日评分变化，但不能因微小排名波动机械地频繁替换股票。

第一版评分可以采用明确的启发式规则，但不得声称未经验证的分数代表盈利概率。

### M3：基本面及信号证据

利用已有 FinanceMCP 财务工具及经过实测可用的 Tushare 批量财务接口，补充 ROE、盈利增长、现金流、估值和财务风险数据。

财务分析必须使用公告日期约束，不能发生历史未来信息泄漏。

增加最小的历史信号效果检验，评估不同市场状态下的信号表现，并区分研究指标和已经具备充分证据的交易规则。

不开发独立回测撮合引擎。

### M4：真实运行验收

使用同仓库 CLI 和系统定时器完成交易日数据更新、分析计算和日报快照发布。

为每份报告保存：

- as-of 交易日、计算时间。
- 数据来源及数据完整性。
- 指标与评分规则版本。
- 市场环境和主要判断依据。
- 股票池及其变化。
- 信号触发条件、失效条件和风险。
- 报告唯一 ID。

核心数据缺失时必须明确输出 NOT_READY，不得隐式使用昨日数据生成今日交易建议。

完成连续至少三个真实交易日的增量更新和报告验收。在无法立即获得三个未来交易日证据时，先交付可验证的历史日期重放、一次真实数据 E2E 和自动调度配置，明确标注连续验收尚未完成，禁止伪造。

## 源码注意事项

特别检查 FinanceMCP `httpServer.ts` 将 Authorization Bearer 解释为 Tushare Token 的逻辑，避免客户端认证和数据源认证相互混淆。

新增的本地分析工具不应进入现有外部数据源 fallback 路由。

检查并修复影响日报计算的 RSI、MACD 口径和时间索引问题。

保留原有 19 个工具的功能，通过可选的工具配置文件或环境变量，为 ChatGPT 日报只暴露少量高级工具。

## 工程实施要求

先阅读和验证现有代码，再做最小修改。不要因为遇到局部问题而重建 HTTP Server、Tushare SDK、回测框架或任务系统。

发现上游成熟功能时直接复用。任何新增依赖必须有明确需求和 ARM VPS 上的实际可运行证据。

每个阶段都运行对应测试，记录真实命令、结果、数据日期、已知限制。一次开发会话应尽可能连续完成 M1 至 M4，不要只写设计文档或在每个小步骤后停止。

最终交付可部署的 FinanceMCP Fork、运行命令、配置说明、ChatGPT MCP Tools、日报样例、测试结果和真实 E2E 验收记录。

优先级始终是：**真实数据可靠 → 每日 MCP 报告可用 → 分析能力逐步增强 → 历史策略证据积累。**
