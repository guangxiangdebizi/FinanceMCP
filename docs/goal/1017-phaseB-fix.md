## 一、P0：修复 OHLC NULL 漏检

检查：

- `src/ashare/audit.ts`
- `src/ashare/ingest.ts`
- `src/ashare/engine.ts`

当前 `audit.ts` 中的 `INVALID_BAR` 未显式检查 `open IS NULL`、`high IS NULL`、`low IS NULL`。

SQLite 的 NULL 比较语义可能导致这些记录绕过异常检查。

### 修复要求

1. 明确检查 OHLC 四个价格字段是否为 NULL。
2. 保留原有的价格非正、最高最低价关系和收盘价越界检查。
3. 检查成交量、成交额缺失时的分类是否一致。
4. 让 `auditDay()` 能准确识别并定位异常股票。
5. 确保 `audit --fix` 只修复对应股票和日期。
6. 让 `checkQuality()` 识别此类异常，不允许静默返回无异常 READY。
7. 保留 V1 评分公式，不能为了修复质量检查而改变 V1 评分权重。

新增反例：分别将 open、high、low、close 设为 NULL，以及 OHLC 数值关系非法。逐个验证审计、质量状态、修补范围和因子快照结果。

如果正式缓存没有上述异常，真实数据上的评分和报告必须保持不变。

## 二、P1：核实历史评价结果的统计口径

### 2.1 不完整样本的解释

当前研究按已完成事件计算收益均值。

但模拟区间仍存在未完成事件和未入场事件。

要求明确：

- 已完成事件的收益是条件观察值。
- 未完成事件仍保留在完整分母中。
- 完成率和无法退出比例应和收益指标一起显示。
- V1/V2 的完成事件集合不完全相同时，不能把均值差当作严格配对的策略收益差。

可以增加基于共同可比较事件的敏感性分析，但不要创建复杂组合回测器。

### 2.2 时间切分名称

V2 在 2026-10-17 才形成。

因此，2026-03-31 只是历史回溯的切分点。

修正文档，明确区分：

- 历史形成区间。
- 回溯模拟验证区间。
- 真正前瞻观察区间。

不能把 2026-04-01 至 2026-10-16 的数据声明为未接触过的样本外结果。

### 2.3 历史结果稳定性

保留现有 V1/V2 历史结果。

核实：

- 形成段 84 个采样日期。
- 模拟段 27 个采样日期。
- 5 个交易日采样间隔。
- 10 个交易日持有期。
- 重叠持有期和不重叠敏感性口径。
- 全市场、沪深 300 和行业基准的完整/部分覆盖状态。

如果未发现计算错误，不应因为 V2 表现不佳而调整参数。

## 三、P1：建立真正的前瞻研究快照

这是本轮的主要新增功能。

从未来实际交易日开始，独立记录 V1/V2 的研究结果。

设计一个简单、可重复执行的命令，例如：

`finance-ashare research-snapshot --date YYYYMMDD`

实际命令可按现有 CLI 结构决定。

### 3.1 执行条件

该命令应：

1. 检查指定日期是否为真实交易日。
2. 检查正式数据质量及报告状态。
3. 只读取该日及之前已经可用的数据。
4. 分别计算 V1 和 V2。
5. 将结果写入独立研究目录或研究数据库。
6. 不修改正式日报、评分和股票池。

如果该交易日尚未产生完整有效数据，应返回 `PENDING` 或明确的错误。

禁止使用后来获取的数据伪装成当日首次研究快照。

### 3.2 快照必须保存的信息

- 交易日。
- 实际计算和保存时间。
- 正式 report_id。
- 数据质量与缺失原因。
- 使用的数据快照标识。
- V1/V2 评分版本。
- 计算代码或构建版本。
- 因子和评分结果。
- 各版本股票池成员。
- 两版评分及成员差异。
- 尚未成熟的未来收益观察状态。

必须保留研究结果生成时实际可见的股票和因子集合。

后续如果数据源修订，不应静默覆盖原始前瞻观察。

可以另行生成修订后重算结果，但应标记为 `REVISED`，并保留原始快照。

### 3.3 后续收益评价

在相应持有期尚未结束时：

- 返回 `PENDING`。
- 不计算假定未来收益。
- 不使用之后的行情生成提前完成的结果。

当持有期结束、退出状态可以确认后，使用现有 `evaluateEvents()` 评价已保存的观察快照。

同一批 V1/V2 研究结果应采用相同的评价方法和数据截止日。

现有正式 V1 股票池与研究 V2 股票池应明确区分。

不需要在本轮创建新 systemd timer。只准备命令和验证脚本，供后续接入现有日频流程。
